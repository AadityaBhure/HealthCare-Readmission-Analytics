A BTech healthcare-analytics mini-project that turns four California datasets into:

* a **backend pipeline** (`run_pipeline.py`) – validation, cleaning, temporally aligned features,
  model training, leakage-aware evaluation and artifact generation;
* a **five-page Streamlit dashboard** (`app.py`) – dark navy/cyan design, KPI cards, Plotly charts,
  county choropleth, hospital-level predictions and a full model-evaluation page;
* an **auto-generated academic report** (`reports/Project_Report.docx` and `.pdf`) built only from
  pipeline outputs;
* **automated tests** (`tests/`) and a **GitHub Actions workflow** (`.github/workflows/pipeline.yml`).

All outputs are hospital- or population-level statistics. The estimates are **not** patient-level
probabilities and are **not** clinically validated.

## Headline results (committed pipeline run)

| CABG next-window readmission rate, held-out 2022-2023 window (n = 118 hospitals) | MAE (pp) | RMSE | R² |
|---|---:|---:|---:|
| Persistence baseline (next = previous) | **2.487** | 3.348 | 0.544 |
| Linear Regression *(recommended by grouped CV on training data)* | 2.543 | 3.438 | 0.519 |
| Random Forest | 2.741 | 3.637 | 0.462 |
| Training-mean baseline | 3.919 | 5.033 | -0.030 |

* Linear Regression minus persistence: **+0.055 pp, 95% bootstrap CI [-0.229, +0.335]**, so there is
  no reliable winner on the one-step horizon.
* **Why persistence is so strong here:** consecutive two-year windows share one calendar year of
  patients (lag-1 correlation r = 0.72, versus 0.47 for non-overlapping windows). On a
  **non-overlapping horizon** persistence degrades to MAE 3.96 pp. Linear Regression reaches
  3.52 pp there and beats persistence in 88% of hospital-grouped CV folds.
* **Separate stroke model** (259 test hospitals): Linear Regression MAE 1.853 vs persistence 1.981
  (−6.4%; CI [−0.268, +0.007]). It is better in 100% of grouped-CV folds.
* **Population:** California all-cause 30-day readmission rate was 15.95% in 2024 (ICD-10), up from
  14.48% in 2016. Medicare patients had the highest rate (17.02%); Self-Pay the lowest (6.98%).

Every number above is regenerated by the pipeline. See `artifacts/` and the Model Evaluation page.

## Quick start (Windows, VS Code terminal)

```powershell
cd healthcare-readmission-analytics
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run_pipeline.py          # ~1 minute: validate -> clean -> train -> evaluate -> artifacts
streamlit run app.py            # opens http://localhost:8501
```

Or do everything with one command:

```powershell
python run_local.py             # runs the pipeline if outputs are missing, then starts the dashboard
python run_local.py --retrain   # force a fresh pipeline run first
python run_local.py --report    # also regenerate the DOCX/PDF report
```

macOS / Linux: use `source .venv/bin/activate` instead of `.venv\Scripts\activate`.
Python **3.12 or newer** is required (pinned packages need it).

Other commands:

```powershell
python -m pytest                       # automated tests (about 1 minute)
python reports/generate_report.py      # rebuild reports/Project_Report.docx + .pdf from artifacts
python run_pipeline.py --report        # pipeline + report in one go
```

The DOCX table of contents is a Word field. Word offers to update it when the file opens (choose
**Yes**), or you can right-click it and choose *Update Field*.

## Datasets (`data/raw/`, never modified)

| ID | File | Role |
|---|---|---|
| A | `cabg_hospital_performance.csv` | Hospital CABG outcomes 2018-2023: the **primary ML experiment** |
| B | `ischemic_stroke_outcomes.csv` | Hospital ischemic stroke readmission/mortality 2011-2015: a **separate** stroke analysis and model |
| C | `california_allcause_readmissions.csv` | All-cause readmissions by year, county and stratum 2011-2024: **population trends** |
| D | `synthetic_cabg_test.csv` | **Synthetic** records for schema/smoke/scenario tests only. Never used for training or evaluation |

The column layouts match HCAI (formerly OSHPD) public reports on the
[CHHS Open Data Portal](https://data.chhs.ca.gov). **Confirm the exact source and licence of your
copies before making the repository public.** Total size is about 0.7 MB.
County boundaries (`data/geo/california_counties.geojson`, 60 KB) come from Plotly's open datasets
(MIT), which are derived from US Census cartographic files. See `tools/build_county_geojson.py`.

Important data issues found and handled (details in `DATA_DICTIONARY.md`):

* CABG two-year windows are **overlapping rolling windows**. The 2020-2021 readmission window covers
  only **2 hospitals**, and missing windows are never bridged.
* Stroke 2013-2014: the deaths/readmissions and cases columns are **transposed** in every row. They
  are swapped back in memory and the fix is logged.
* All-cause: ICD-9 (2011-2015) and ICD-10 (2016-2024) are kept as separate series. 2015 is a partial
  year, and suppressed values stay missing (never zero).

## Method in one paragraph

Each training example pairs a hospital's inputs from window *t* with its readmission rate in window
*t+1*. The inputs are the previous readmission rate, the post-operative stroke rate and CABG volume.
Transitions are created only when the target starts exactly one year later. Models are trained on
earlier transitions and evaluated **once** on the latest window (2022-2023). The recommended model
and the Random Forest hyper-parameters are chosen by **hospital-grouped cross-validation inside the
training set**. All learned preprocessing lives inside scikit-learn Pipelines, which are fitted on
training rows only. Every model is compared with **persistence** and **training-mean** baselines on
the same hospitals, with paired bootstrap CIs. Sensitivity analyses cover pooled grouped CV, a
non-overlapping horizon and an extended feature set. Explainability uses permutation importance,
standardised coefficients, exact Linear Regression contributions, a learned response curve and
error-by-volume analysis.

## Deploying the dashboard (Streamlit Community Cloud)

1. Sign in at <https://share.streamlit.io> with GitHub and click **Create app → Deploy a public app from GitHub**.
2. Repository: `YOUR-GITHUB-USERNAME/healthcare-readmission-analytics`, branch `main`, main file `app.py`.
3. **Advanced settings → Python version: 3.12** (3.13 also works).
4. Click **Deploy**. The repository already contains the trained models and artifacts, so the app
   starts without retraining. If they were missing, the app would run the pipeline once at start-up.
5. Copy the app URL (e.g. `https://<name>.streamlit.app`) into the **Open Live Dashboard** link
   above. Optionally also set it in `src/config.py` (`LIVE_DASHBOARD_URL`) so the report title page
   shows it.

Visitors only need a browser. No Python, VS Code or dataset download is required.

## Running the pipeline on GitHub (GitHub Actions)

* **Actions → Run analytics pipeline → Run workflow** (this needs write access to the repository).
* The workflow installs dependencies and checks that the data files exist. It then runs the tests,
  runs the pipeline, regenerates the report, writes a results summary and uploads everything as a
  downloadable workflow artifact.
* Tick **commit_artifacts** to push the refreshed `models/`, `artifacts/` and `reports/` back to
  `main`. Streamlit Community Cloud then **redeploys automatically** from that commit. If your
  organisation restricts tokens, enable *Settings → Actions → General → Workflow permissions →
  Read and write*.
* The workflow and the website are **separate services**. Running the workflow does not open the
  dashboard; the dashboard simply serves whatever is committed on `main`.
* The same workflow also runs (without committing) on pushes and pull requests to `main`.

No GitHub token is stored in the code. The optional commit uses the workflow's built-in
`GITHUB_TOKEN`.

## Optional: read data from a GitHub raw URL

By default the app reads `data/raw/`. To read the CSVs over HTTPS instead, set these (environment
variables, or root-level keys in `.streamlit/secrets.toml` on Streamlit Cloud):

```toml
READMISSION_DATA_SOURCE = "github"
READMISSION_DATA_BASE_URL = "https://raw.githubusercontent.com/YOUR-GITHUB-USERNAME/healthcare-readmission-analytics/main/data/raw"
```

## Testing

`python -m pytest` covers:
* dataset loading, encodings and required columns;
* rate/count parsing, and that missing values stay missing;
* the stroke column-swap fix and ICD-era separation;
* reporting-period alignment (no gap bridging);
* feature/target separation and leakage guards (training-only preprocessing, disjoint train/test
  windows, synthetic isolation);
* model training/prediction and train/inference schema consistency;
* integrity of the saved models, synthetic scenario tests and the end-to-end pipeline;
* a clear error when data files are missing;
* every dashboard page via Streamlit `AppTest`, including interactions;
* report generation.

## Responsible use

Aggregated hospital/population statistics only, with no patient records. The estimates are
hospital-level risk-adjusted rates, not individual probabilities. They do not identify causes and
are not clinically validated. Demographic differences are associations, not causal effects.
Synthetic results are never evidence of real-world performance.
